# 大数据运维 SOP 手册

适用场景：大数据智能体执行日常巡检、数据链路排查、容量评估、紧急止血等运维任务时，按本手册的标准流程操作。

---

## 1. 每日巡检 SOP

巡检目标：快速发现集群异常，在用户发现前处理。

### 1.1 巡检清单（按顺序执行）

```
1. YARN 集群资源
   → 查集群资源指标：内存使用率 > 85% 告警，VCores 使用率 > 90% 告警
   → 查节点列表：关注 LOST/UNHEALTHY 节点

2. Flink 作业状态（Dinky）
   → 查作业实例列表：关注 FAILED/RUNNING 异常作业
   → 异常作业 → 查作业详情定位错误

3. DolphinScheduler 调度
   → 查流程实例列表（最近 24h）
   → 关注 FAILED/NEED_FAULT_TOLERANCE 状态
   → 失败任务 → 查任务实例日志

4. 存储健康
   → HDFS：查根目录汇总，总用量 > 80% 告警
   → Doris：查 BE 节点列表，关注 Dead 节点和磁盘使用率

5. 数据质量
   → 检查关键表的行数变化趋势（与昨天对比）
   → 异常波动 > 30% 需排查
```

### 1.2 巡检报告模板

```
📊 大数据集群巡检报告 — {日期}

一、资源概况
- YARN：总内存 {X}GB，已用 {Y}GB（{Z}%），VCores {a}/{b}
- HDFS：总容量 {X}TB，已用 {Y}TB（{Z}%）
- 节点：共 {N} 个，健康 {M} 个，异常 {K} 个

二、作业状态
- Flink 运行中 {A} 个，失败 {B} 个
- DolphinScheduler 今日执行 {C} 个，成功 {D} 个，失败 {E} 个

三、异常项及建议
- [异常] xxx → [建议] xxx
- [告警] xxx → [建议] xxx

四、风险预警
- 磁盘将在 {N} 天后用尽（按当前增长速率）
- {队列名} 队列资源紧张，建议扩容
```

## 2. 数据链路排查 SOP

当用户反馈"数据没有"或"数据不对"时，按链路逐层排查。

### 2.1 标准排查流程

```
数据链路：源头 → 同步 → 消息队列 → 计算 → 存储 → 查询

逐层排查：

1. 源头数据是否正常？
   → 直接查源数据库，确认数据存在且时间范围正确

2. 同步任务是否正常？
   → SeaTunnel/DataX：查任务状态和日志
   → Flink CDC：查作业是否在运行，有无报错
   → 对比源表和目标表行数

3. 消息队列是否有数据？
   → Kafka：查 Topic 的消息写入速率
   → 查消费者组 Lag 是否在增长

4. 计算任务是否正常？
   → Flink/Spark 作业状态
   → 查作业日志中的异常和警告

5. 目标存储是否有数据？
   → Doris/ClickHouse：`SELECT count(*), max(create_time) FROM table`
   → HDFS：检查文件时间戳和大小

6. 查询层是否有权限/配置问题？
   → 检查表权限和路由配置
```

### 2.2 常见数据问题速查

| 现象 | 可能原因 | 排查方向 |
|------|---------|---------|
| 数据量为 0 | 同步任务未运行 | 查 SeaTunnel/DataX 任务状态 |
| 数据量突然下降 | 源头数据减少 / 同步任务部分失败 | 对比源表 + 查同步错误日志 |
| 数据延迟 | CDC 延迟 / 消费积压 | 查 Kafka Lag + Flink Checkpoint |
| 数据重复 | 重复写入 / 语义 exactly-once 失效 | 查写入幂等配置 |
| 字段值为 NULL | 类型转换失败 / 源表 Schema 变更 | 对比 Schema + 查转换日志 |

## 3. 容量评估 SOP

### 3.1 评估维度

```
1. 计算资源（YARN）
   → 近 7 天 YARN 集群 metrics 趋势
   → 峰值使用率 > 80% → 建议扩容
   → 关注队列级别的使用率

2. 存储资源（HDFS / Doris）
   → HDFS 近 7 天增量 → 预测 N 天后满盘
   → Doris BE 磁盘使用率 > 75% → 建议扩容
   → 清理过期数据释放空间

3. 消息队列（Kafka）
   → Topic 数据量趋势
   → 消费者 Lag 趋势
   → 分区数是否足够

4. 调度资源（DolphinScheduler）
   → Worker 负载率
   → 任务排队时间趋势
```

### 3.2 容量报告模板

```
📈 容量评估报告 — {日期}

一、计算资源
- YARN 集群峰值使用率：内存 {X}%，CPU {Y}%
- 趋势：{近 7 天趋势描述}
- 建议：{是否需要扩容，扩多少}

二、存储资源
- HDFS 使用率：{X}%（{Y}TB / {Z}TB）
- 日均增量：{N}GB
- 预计 {M} 天后需要扩容
- 建议：{清理策略 + 扩容计划}

三、消息队列
- Kafka 总数据量：{X}TB
- 最大消费者 Lag：{N}
- 建议：{是否需要增加分区/消费者}
```

## 4. 紧急止血 SOP

当生产环境出现严重故障时，按优先级执行。

### 4.1 止血优先级

```
P0（立即执行）：停止故障源头
  → 杀掉 YARN 异常应用 / 取消 Dinky 异常作业
  → 停止异常同步任务
  → 暂停异常调度工作流

P1（5 分钟内）：恢复核心服务
  → 重启故障组件（NodeManager / DataNode / Broker）
  → 切换主备（NameNode / ResourceManager HA）

P2（30 分钟内）：修复数据
  → 回滚到上一个正常的 Checkpoint/Savepoint
  → 修复后从断点恢复
  → 补数据（回填历史数据）

P3（事后）：根因分析
  → 收集所有相关日志
  → 分析根因并制定改进措施
  → 更新监控告警规则
```

### 4.2 常见紧急场景

| 场景 | 第一步 | 第二步 | 第三步 |
|------|--------|--------|--------|
| Flink 作业异常写入脏数据 | cancel 作业 | 修复代码 | 从 Savepoint 恢复 + 回填 |
| HDFS 磁盘满导致写入失败 | 清理临时文件/过期数据 | 扩容 DataNode | 调整数据保留策略 |
| Kafka 全部消费者挂掉 | 重启消费者 | 排查消费者死因 | 增加消费者冗余 |
| DolphinScheduler 调度全卡 | 查 Worker 状态 → 重启 | 清理僵尸任务 | 扩容 Worker |
| Doris BE 全部宕机 | 逐个重启 BE | 检查 Tablet 副本 | 恢复后校验数据 |

## 5. 集群变更 SOP

任何集群变更都应遵循：**备份 → 灰度 → 验证 → 全量**

### 5.1 配置变更

```
1. 备份当前配置
2. 修改配置
3. 灰度生效（单节点/单作业）
4. 验证功能正常
5. 全量生效
6. 监控 30 分钟确认稳定
```

### 5.2 版本升级

```
1. 测试环境验证兼容性
2. 备份元数据（Hive Metastore / Doris FE / DS 数据库）
3. 灰度升级（单节点）
4. 验证读写正常
5. 全量升级
6. 回滚方案准备好（备份 + 旧版本包）
```
