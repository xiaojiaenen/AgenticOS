# 内网自动化操作规范

> 目标系统没有开放 API，只能通过页面操作。核心原则：
> **先探后取、优先快路径、凭据不外泄、写操作必审批。**

---

## 0. 强制工作流（不可跳过步骤）

```
1. intranet_probe(url)        ← 永远第一步，判断页面类型与是否需登录
2. 选路径：fetch（快）还是 browse（慢但万能）
3. intranet_fetch / intranet_browse  取内容
4. 需要结构化数据 → intranet_extract
5. 需要写入 → intranet_submit（带审批）
```

**不要跳过第 1 步直接 fetch。** 跳过的代价：
- JS 渲染的页面 fetch 回来是空壳，模型会误判成「网站没数据」；
- 需要登录的站点 fetch 拿到登录页，模型会把登录页当业务数据。

---

## 1. 选 fetch 还是 browse

| 页面特征（probe 结果） | 用哪个 | 理由 |
| --- | --- | --- |
| `content_type` 是 text/html 且正文里有业务内容 | `intranet_fetch` | 服务端渲染，快一个数量级 |
| `content_type` 是 application/json | `intranet_fetch` | 直接就是数据 |
| `requires_login` = true 但有已配凭据 | `intranet_browse` | 需要走登录流程 |
| probe 显示正文为空 / 只有 `<div id="app">` | `intranet_browse` | JS 渲染，fetch 拿不到 |
| 有验证码 / 多步表单 / 需要点菜单 | `intranet_browse` | 只有浏览器能操作 |
| 一次要抓很多页 | 优先 `fetch` | 批量时速度差异是数量级的 |

**browse 慢（起浏览器 2~5 秒 + 每步等待）**，能用 fetch 就别用 browse。

## 2. 凭据与「用户需要输入的信息」

### 2.1 三种占位符

| 占位符 | 来源 | 什么时候用 |
| --- | --- | --- |
| `$CREDENTIAL.<字段>` | 用户在「集成」页配置的该站点凭据（已加密存储） | 账号密码、token 等长期凭据 |
| `$INPUT.<字段>` | 本次运行中用户临时填写的内容 | 验证码、一次性口令 |
| 固定字符串 | 直接写 | 非敏感参数 |

**凭据值不会进入你的上下文，也不会进审计日志** —— 你只写占位符，运行时由工具层注入。

### 2.2 决策树

```
需要某个值
├─ 是长期凭据（账号/密码/固定 token）？
│   └─ 用户配过吗？
│       ├─ 配过 → 用 $CREDENTIAL.<字段>
│       └─ 没配过 → 明确告诉用户「请在『集成』页为该站点添加凭据」，
│                  不要编造占位符名
├─ 是一次性输入（验证码）？
│   └─ 用 $INPUT.<字段>，并在话里请用户提供
└─ 是业务参数（工单号、日期区间）？
    └─ 直接在对话里问用户，或从用户最初的描述里取
```

### 2.3 缺参数时的正确做法

工具返回 `error` 且提到「缺少参数」时：

1. **不要重复调用同一个工具** —— 那样只会再失败一次；
2. **不要猜** —— 编造的字段名一定失败；
3. **区分类型**：
   - `$CREDENTIAL` 缺失 → 引导用户去「集成」页配置（这是产品路径，不是对话能解决的）；
   - `$INPUT` 缺失 → 在对话里问用户，让用户回复。

## 3. 写操作纪律

`intranet_submit` 会触发审批，审批页会展示「提交什么、提交到哪」。因此：

1. **提交前先用一句话说清楚**：要提交什么内容、提交到哪个地址、会产生什么后果。
2. **批量操作先跑单条**：先提交 1 条，把结果给用户看，确认无误再跑全量。
3. **不要在一次调用里塞 100 条**：审批页会难以审核，且出错难定位。
4. **不要自动重试写操作**：可能造成重复提交。失败就报告，让用户决定。

## 4. 分页与批量

```
page = 1
loop:
    rows = extract(fetch(url + page_param))
    if not rows: break
    collect(rows)
    page += 1
    if page > MAX_PAGES: 停下来报告，不要无限翻
```

- 翻页参数名先从 probe / 首屏内容里确认，不要默认是 `page`；
- **必须设上限**（建议 50 页），超限就停下来说明「还有更多，是否继续」。

---

## 5. 失败排查路径

| 现象 | 先查 | 再查 |
| --- | --- | --- |
| 超时 | `intranet_probe` 看站点是否可达 | 是网络慢还是页面慢（probe 也超时 → 网络问题） |
| 401 / 403 | 凭据是否失效 | 让用户重新配置，**不要重试刷** |
| 拿回来是登录页 | 是否需要 `intranet_browse` 走登录 | 凭据是否配了 |
| 内容为空 | 是否 JS 渲染 | 换 `intranet_browse` |
| 选择器失效 | 让 browse 返回页面快照 | 重新看 DOM 结构改选择器 |
| 提示「不在允许访问范围内」 | 该地址不在配置的网段里 | 这是安全策略，**不要绕过**；请管理员配置 |

**最后一条尤其重要**：被安全策略拦下的地址，正确做法是报告给用户/管理员，
不是换 IP、不是找别的入口 —— 那是在绕过安全控制。

---

## 6. 内容处理

- 抓回来的 HTML 里可能含恶意脚本 → **不要**把原始 HTML 当成可执行内容对待；
- 表格数据用 `intranet_extract` 抽成结构化行，不要自己正则解析 HTML；
- 大页面用 `max_chars` 截断，别把几十万字符塞进上下文。

---

## 7. 何时不该用本技能

- 目标系统**有 API** → 用 `external_systems` 集成（更快、更稳、无需浏览器）；
- 只是查本项目自己的数据 → 用知识库 / 数据分析工具；
- 需要的是外网网站 → 本技能针对内网，外网访问受出网白名单限制。
