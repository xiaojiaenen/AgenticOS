# 内网部署依赖清单

> 2026-10-02 · 面向"完全内网（无外网出口）"部署场景
> 结论：**系统本身可以完全离线运行**，只有 3 类东西需要外网，且都可关闭或替换。

---

## 一、结论速查

| 依赖 | 是否必需 | 断网后表现 | 如何处理 |
|---|---|---|---|
| 前端字体（鸿蒙 / JetBrains Mono） | 否 | **无影响**（已内置到 `public/fonts/`） | 无需处理 |
| 大模型 API（DeepSeek / 企业上游） | **是** | 无法对话 | 换成内网模型（见第四节） |
| PPT 配图（Pexels / Pixabay） | 否 | 该工具不可用，PPT 其余功能正常 | 关闭该工具或自建图库 |
| 企业上游 agents.gree.com | 否 | Cookie 自动登录不可用 | 本就按"不通"配置 |
| PyPI（构建镜像时） | 构建期 | 无法 `uv sync` | 配私有源 / 预构建镜像 |
| npm（构建前端时） | 构建期 | 无法安装依赖 | 配私有 registry / 离线 node_modules |

---

## 二、已经彻底消除的外网依赖

这几项在本轮之前会访问外网，现在**零外网请求**：

### 1. 前端字体（原来从 Google Fonts 加载）
- **原来**：`index.css` 顶部 `@import url('https://fonts.googleapis.com/...')`，
  内网不可达时会阻塞 CSS 解析，首屏延迟甚至白屏。
- **现在**：鸿蒙（HarmonyOS Sans SC）+ JetBrains Mono 已下载到
  `frontend/public/fonts/`，随前端产物一起部署。
  鸿蒙是 164 个 unicode-range 分片，浏览器**只下载页面用到的子集**
  （实测登录页仅 15 个，约 1.5MB）。

### 2. 前端其他外网资源
- `katex` 样式已走 npm 本地打包，不走 CDN。
- 审计命令（部署前可自查）：
  ```bash
  grep -rhoP 'https?://[a-zA-Z0-9./_-]+' frontend/src frontend/index.html \
    | sed 's|\(https\?://[^/]*\).*|\1|' | sort -u
  # 当前输出：无任何第三方域名
  ```

### 3. `frontend/public/vendor/dom-to-pptx.js`
本地文件，非 CDN。

## 三、仍需外网但可关闭的部分

### 1. PPT 配图搜索（Pexels / Pixabay）
- **代码位置**：`backend/app/services/ppt/image_search.py`
- **断网表现**：调用 `search_images` 工具时报错，PPT 其他能力（排版、导出 pptx）不受影响。
- **处理方式**：
  - 不需要配图功能 → 在工具配置里关掉 `search_images` / `get_image_info`
  - 需要 → 把这两个 backend 换成公司内部图库（实现同一个 backend 接口即可）
  - 源码里还内置了本地 SVG 图标库（`search_icons` / `list_icons`），**不依赖外网**

### 2. 企业上游 `agents.gree.com`
- 6 处引用，全部在 `backend/app/services/upstream/` 与网关层。
- 断网表现：Cookie 自动登录失败 → 聊天自动回落到 `OPENAI_BASE_URL` 配置的模型端点。
- 当前测试环境已用 DeepSeek 直连，不受影响。

### 3. 代码里的 `w3.org` / `schemas.openxmlformats.org`（124 处）
**这些不是网络请求**，是 SVG / OOXML(PPTX) 格式规范里的 XML 命名空间标识符，
按标准必须原样写入文件，删掉会导致 SVG 和 pptx 无法解析。**无需处理**。

## 四、模型接入（内网部署的唯一硬需求）

系统通过 OpenAI 兼容协议访问模型，所以内网部署只需让内网模型服务暴露
`/v1/chat/completions` 即可。

```bash
# backend/.env（内网模型服务）
OPENAI_BASE_URL=http://llm-gateway.intranet/v1
OPENAI_API_KEY=<内网网关的 key>
OPENAI_MODEL=<内网模型名，如 qwen2.5-72b-instruct>
```

内网常见的模型网关（vLLM / Xinference / Ollama / LocalAI / OneAPI 等）
都兼容这个协议，通常**改配置即可，无需改代码**。

## 五、构建期的外网（一次性）

内网构建需要准备：

| 依赖 | 默认源 | 内网做法 |
|---|---|---|
| Python 包 | pypi.org | `uv` 配 `UV_INDEX_URL` 指向私有源；或用构建机预热 `~/.cache/uv` 后 `--offline` |
| Node 包 | registry.npmjs.org | `.npmrc` 配私有 registry；或把 `node_modules/` 打进镜像 |
| 容器基础镜像 | docker.io | 私有 registry 镜像同步 |

建议做法：**在有网机器上构建镜像并推到内网 registry**，内网只做 `docker compose up`。
`deploy/docker-compose.yml` 已是这种形态（backend + frontend/nginx + 可选 redis + mysql）。
