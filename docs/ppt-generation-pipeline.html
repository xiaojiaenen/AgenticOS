解析整个 PPT 生成链：从 Prompt、工具、SVG 到原生 .pptx

AgenticOS 的 PPT 能力不是“让模型吐一段 SVG”这么简单，而是一条完整的生产管线： 先用 Prompt 和动态注入把模型约束到可导出的 SVG 结构，再通过会话目录累积 slide_N.svg，随后组装成 artifact，并在导出阶段继续做图标嵌入、图片对齐、 tspan 扁平化、圆角修复与 DrawingML 转换，最终得到可编辑的原生 PowerPoint。

1. 约束生成

PPT_SYSTEM_PROMPT 强制模型用 save_slide 逐页写盘； _inject_design_catalog() 再追加主题、layout、token、craft rules。

prompts.py _inject_design_catalog

2. 工具协作

PPT 模式额外注册了读写幻灯片、图标搜索、图表坐标、质量检查、PPTX 反向转换、模板导入等工具。

ppt_tools.py icon_tools.py chart_tools.py

3. Artifact 组装

会话结束后从 data/ppt-sessions/<session_id> 读取 SVG，校验页数和 viewBox，解析主题 token，生成预览 HTML 并入库。

ppt_artifact_service.py PptArtifactModel

4. 原生导出

导出前还会做一次 SVG 后处理，然后进入 create_pptx_with_native_svg()， 拼出真正的 PPTX 包结构和动画、备注、媒体资源。

export_pptx pptx_builder.py

二、导出引擎分解图：artifact 如何变成可编辑的 PowerPoint

生成阶段结束时拿到的只是“可预览的 SVG artifact”；真正导出时还要再走一次严肃的结构清理与 Office 包组装。 这也是为什么系统既有 PptArtifactService，又有 svg_to_pptx 整个子系统。

为什么导出前还要再处理一次 SVG

  • artifact 阶段的目标是“浏览器里能预览且能存档”，导出阶段的目标是“Office 里能稳地转成原生形状”。
  • data-icon 这种占位语法必须先展开，否则 builder 并不知道具体 path 是什么。
  • 多层 tspan、某些圆角矩形和图片布局，在浏览器里没问题，但在 PPTX 结构层需要更保守的形态。
  • 因此导出阶段会进行第二次清洗，它和 artifact 组装不是同一层的工作。

builder 的真正产物不是一张图

  • 每页都会生成 slide XML、relationships、media 文件，必要时还会带 notes、transition、timing、narration。
  • 如果启用兼容模式，还可能预渲染 PNG，兼顾老版本 Office。
  • 最终输出是完整 OOXML 包，而不是把 SVG 丢进 zip。

三、PPT 工具栈与文件产物图

这一部分把“工具在什么时候介入”和“关键文件/目录在什么时候出现”放到同一个视图里，方便你调试具体阶段出了什么问题。

生成期目录

data/ppt-sessions/<session_id>/slide_1.svg
slide_2.svg ...

这是模型逐页写入的工作目录，也是后续修改已有 deck 时 read_slide() 的读取来源。

artifact 期目录

data/ppt-output/<artifact_id>/source_slide_N.svg
preview.html

这是便于人工检查的调试副本，不是运行时唯一数据源。

数据库产物

PptArtifactModel.deck_json 保存主题名和 SVG 数组，
preview_html 保存浏览器预览文档，
metadata_json 保存来源和统计信息。

PPT 模式下的关键工具职责

  • save_slide：唯一正式落页工具，把单页 SVG 写进会话目录。
  • read_slide：修改已有 deck 时先把旧页读出来。
  • search_icons：把语义关键词转成可嵌入的 data-icon 名称。
  • calc_chart_positions：图表先算坐标，再写 SVG，避免“拍脑袋布局”。
  • check_svg_quality：检查 XML 合法性、viewBox、一致性、禁用元素、文本问题等。
  • convert_pptx_to_svg：把已有 PPTX 拉回同一条 SVG 编辑链。
  • import_pptx_template：用于提取模板母版、布局、颜色和资产，不直接产出 deck。

失败最常见会卡在哪几层

  • 生成层：模型没按约束使用 save_slide，或者页数不足 3 页。
  • 结构层：某页没有 viewBox、主题名不合法、含未转义文本、存在非法元素。
  • artifact 层：validate_svg_slides() 失败，导致没有 artifact。
  • 导出层：图标未展开、tspan 结构复杂、圆角/图片兼容问题，或 builder 内部转换失败。

四、反向编辑与模板导入：为什么这条链不是单向的

AgenticOS 的 PPT 系统并不只服务于“从零生成”。它还提供了两条逆向入口，让现有 PPT 或设计模板也能进入统一的 SVG 工作流。
