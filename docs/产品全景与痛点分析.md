# AgenticOS 产品全景与痛点分析

> 2026-10-02 · 用于回答"这个系统解决什么问题、每个功能在解决哪一环"

---

## 一、一句话定位

**AgenticOS 是面向企业内部的自建 AI Agent 平台**：把"公司的大模型能力"从"个人聊天玩具"变成"受管控的生产力工具"——员工在网页里用自然语言驱动 Agent 完成真实工作（查知识、写材料、生成 PPT、建网站、调内部系统），而全程数据不出内网、危险操作有人把关、成本和用量可观测。

它对标 Dify / Coze / n8n 的交集，但选择了一条不同的路：**不做通用低代码编排，做"开箱即用的办公场景 + 强管控的企业底座"**。

---

## 二、它解决的痛点（为什么企业需要它）

### 痛点 1：通用 AI 聊天工具解决不了"干活"
员工拿 ChatGPT 问业务问题，得到一段话，但要用的结果是一份能发出去的 PPT、一个能打开的网页、一份口径正确的材料。通用聊天工具没有产出物、没有工具、没有交付形态。
→ **AgenticOS 的回答**：把"聊天"升级成"交付"——PPT 产出可编辑 .pptx、网站产出可预览可部署的工程、知识库回答带出处。

### 痛点 2：AI 会乱来，关键操作没人敢让它碰
企业最怕 AI 误删文件、误改配置、误发邮件。市面上要么不敢给权限（AI 变成玩具），要么全放开（出事没人担责）。
→ **AgenticOS 的回答**：HITL 人工审批（工具级 + 子操作级粒度）。写文件、发邮件、部署上线都要人点"批准"，并且能看到参数预览。

### 痛点 3：数据不能出内网，但知识要能被问出来
公司资料在内部系统里，公网 AI 一问就泄露。自建方案又普遍"难用"。
→ **AgenticOS 的回答**：完全私有化部署（Docker Compose 起两个服务），知识库 RAG 全程本地（jieba 分词 + MySQL 全文索引），支持 OpenAPI 导入把内部系统变成工具。

### 痛点 4：每个部门都要自己的 AI，IT 排不过来
业务方想调提示词、调工具权限，IT 改一次要发版。
→ **AgenticOS 的回答**：**用户自建智能体**（身份 + 提示词 + 工具勾选 + 可见范围），IT 不用参与；管理员仍可管控内置智能体。

### 痛点 5：AI 用起来花了多少钱、干了什么活，没人知道
→ **AgenticOS 的回答**：管理后台记录每次运行的 token、耗时、工具调用、模型分布、用户排行。

## 三、功能全景（每一环在系统里的位置）

### 3.1 交互层：统一入口

| 功能 | 说明 | 解决什么 |
|---|---|---|
| 多模式聊天 | 通用 / PPT / 网站 / 邮件 / 大数据运维 五种模式，各自系统提示词与默认工具集 | 一个入口覆盖不同岗位的任务类型 |
| SSE 流式输出 | 正文、思考过程、工具调用按真实顺序逐段到达 | 长任务不"假死"，能看到 Agent 在想什么、在做什么 |
| 按序渲染 | `思考条 → 工具卡 → 正文` 交错展示（对齐 ChatGPT/Claude 观感） | ReAct 过程透明可审 |
| 会话管理 | 新建/搜索/删除/历史恢复，刷新后回到原会话 | 上下文不丢 |
| 产物预览面板 | PPT / 网站产物右侧面板直接预览，刷新后自动恢复 | 产出物当场可见 |
| 提示词润色 | 一键把口语化需求改写成结构化长提示词，可取消还原 | 普通人也能写出好 prompt |
| 智能体商店 | 安装同事分享的助手，或自建（名称/模式/提示词/36 个工具勾选/可见范围） | 能力复用 + 业务方自助 |

### 3.2 能力层：Agent 能做什么

| 能力 | 实现要点 | 解决什么 |
|---|---|---|
| 36 个工具 | 计算、时间、文件、Python、Git、npm、Skill、记忆、知识库、邮件、图表、数据分析、PPT 制作、网站构建部署等，分 7 类 | Agent 有手，能真的干活 |
| 工具级审批 | 每个工具可单独开关 + 标记"需人工审批" | 危险操作可控 |
| 多智能体编排 | leader-worker 图（`multi_agent_graph_service`） | 复杂任务可拆给多个角色并行 |
| 异步子 Agent | 后台任务（代码分析、文件处理） | 长任务不阻塞对话 |
| 外部系统集成 | 8 个预设（HDFS/YARN/Doris/Dinky/DolphinScheduler/OpenSpider…）+ OpenAPI 导入 + JWT/Token/Basic/签名鉴权 | AI 能调公司的内部系统 |
| MCP 支持 | 标准协议接入外部工具 | 生态扩展 |

### 3.3 交付层：产出什么

| 产物 | 技术路径 | 价值 |
|---|---|---|
| PPT | SVG 原生绘制 → 预览 HTML → 导出**形状可编辑的原生 .pptx**（5 套视觉主题、10 种版式） | 拿去就能改，不是一张图 |
| 网站 | 模板初始化（vanilla/React/Vue）→ 构建 → 资源内联预览 → 审批部署 | 从一句话到可访问的站点 |
| 知识库问答 | 文档解析（markitdown）→ Wiki 自动编译（摘要/概念/事实三类页面）→ 中文 BM25 检索 | 答案有出处、可持续扩充 |
| 数据分析 | analyze_data（概览/统计/分组/相关性/趋势）+ 图表渲染 | 不只是算数，是给结论 |

### 3.4 记忆层：越用越懂你

- **L0 原始对话 → L3 蒸馏事实**的多层记忆流水线
- 检索双通道：BM25（关键词精确）+ 向量（语义近似）
- 记忆可管理：管理员可见、可删，用户对话中自动提取

### 3.5 企业底座：可管、可控、可观测

| 能力 | 说明 |
|---|---|
| 认证与组织 | 本地账号 + LDAP（企业目录登录）、RBAC（admin/user）、首个用户自动成为管理员 |
| 频率与安全 | Redis 限流、凭据 Fernet 加密（生产强制独立密钥）、API Key 哈希存储、CSP 沙箱预览 |
| 数据看板 | 运行次数、token 消耗、模型分布、工具排行、用户热区、趋势图 |
| 公告 | 用户进系统看到的公告，支持 AI 生成 |
| 审计 | 每次运行的完整用量与工具轨迹入库 |

### 3.6 工程底座

- **技术栈**：FastAPI + SQLAlchemy 2.0 + Alembic + React 19 + TS strict + Tailwind 4 + shadcn/ui + Vitest/ESLint
- **质量门**：后端 238 测试 + ruff、前端 49 测试 + eslint + Chrome 85 CSS 兼容门禁 + CI 全流水线
- **兼容**：Chrome 85 优雅降级（hex 色板不用 oklch）、深浅双主题、移动端适配
- **产物版本**：PPT 每轮入库成版本、网站每轮快照，用户可回看历史版本

## 四、与通用聊天工具 / 通用 Agent 平台的差异

| 维度 | ChatGPT 等通用工具 | Dify/Coze 等平台 | **AgenticOS** |
|---|---|---|---|
| 部署 | 公网 SaaS | 私有化为主 | 私有化为主，Compose 两服务起完 |
| 产出物 | 文字/图片 | 工作流跑出的数据 | **可编辑 PPTX、可部署网站、带出处的知识库答案** |
| 权限 | 只能聊 | 靠平台配置 | **工具级审批，业务方自建自控** |
| 内部系统 | 无 | 插件/MCP | **预置大数据平台集成 + OpenAPI 导入** |
| 使用门槛 | 零 | 学习工作流编排 | 会说话就能用 |

## 五、当前阶段的取舍与已知边界

**有意不做**：通用工作流画布（面向的是"说需求就能干活"而非"编排流程"）、多租户计费（当前定位企业内部单租户）、向量库（用 MySQL 全文索引兜住，量大再引入）。

**已知边界**：
1. 上游模型与 Cookie 模式依赖配置，测试环境用 DeepSeek 等 OpenAI 兼容端点验证
2. 网站版本回溯目前是"快照式"（每轮一份自包含 HTML），未做差异对比
3. 流式按序渲染在**刷新后**的历史消息上会退化为旧布局（需后端补 seq 才能重建，见 B 档方案）
4. 企业上游（agents.gree.com Cookie 自动登录）需企业侧网络可达才可用
