## 2. 已确认的关键决策（来自仓库既有文档）

### 2.1 架构与技术栈（`docs/development-plan-v2.md`、`docs/enterprise-upgrade-plan.md`）

- 前端：React + Vite（dev 端口 `3001`），组件体系统一到 **shadcn/ui**，**移除旧样式与玻璃拟态**，`tsconfig` 开 `strict`。
- 后端：Python `>=3.13,<3.14`，FastAPI + SQLAlchemy + **alembic** 迁移；生产库 **MySQL**（开发可 SQLite，**不用 PostgreSQL**）；拆分 `agent_service`；替换自研/外部轮子以适配内网。
- 兼容性硬约束：**Chrome 85 优雅降级**（CI 门禁 `npm run verify:css` 禁止未加兜底的 `oklch / color-mix`）——否决性条件。

### 2.2 办公能力（`docs/调研-Univer办公能力接入.md`）

- Univer v1.0.3 只能**部分接入**且要求 Chrome 88+；图表、透视表、xlsx 导入导出、打印、协同、版本历史均为 **Univer Pro 商业能力**，开源版没有 → 需自研或换方案。
- 两个已记录的渲染坑：标题样式必须走 `paragraphStyle.namedStyleType` 且 `HEADING_1` 从 `4` 开始；文档 `dataStream` 末尾最后一个 `\r` 后必须补 `\n`，否则整页空白。

### 2.3 字体与离线化（`docs/字体说明.md`、`docs/内网部署依赖清单.md`）

- 中文 **HarmonyOS Sans**、西文 **JetBrains Mono**，自托管于 `public/fonts/`，**不使用外部 CDN**。
- `chart.js` 已本地化（提交 `00826a5`），预览 iframe 零外网请求。
- 结论：**离线内网部署可行**，真正必需的外部依赖只有 LLM API；图片搜索、企业上游集成属可选/可替换。

### 2.4 本地电脑 Agent 化（`docs/调研-本地电脑Agent化方案.md`）

- **本次不实现，仅调研**。
- 硬约束：Win7 支持止于 2020-01-14、ESU 止于 2023-01-11、Chrome/Edge 109 是 Win7/8.1 最后可用版本 → 浏览器扩展与新版 Web API 路线在 Win7 上不可行。

### 2.5 组织级知识库（`docs/AgenticOS知识库系统设计方案.md`）

- 在现有 per-user 记忆（L0→L1→L2→L3 + BM25/向量/RRF）之上新增 **per-org 知识库**。
- 核心主张：**编译优于检索**（LLM 先把原始文档编译成 Wiki 页面，而非每次查询临时 RAG）；三层 = 原始文档层 → Wiki 编译层 → Agent 对话层。
- 新增 6 张表：`knowledge_bases` / `kb_documents` / `kb_wiki_pages` / `kb_wiki_links` / `kb_ingest_tasks` / `kb_review_items`。
- 关键设计：`purpose` 目标声明（界定 LLM 该关注/不该关注什么）、`page_type` 七类枚举、`authority_level` 权威分级、`conflicts_json` **矛盾显式化**（不静默覆盖，进人工 Review 队列）。

### 6.3 最后修复的缺陷根因（Release Note 可直接引用）

`d9731da fix(sheet): 补版本条` 的三层叠加原因：
1. 表格产物字段已从 `artifactId` 统一为 `artifact_id`，但**版本快照仍读旧 camelCase key** → `reference` 为 `None`；
2. 因此 `snapshot_sheet_version` 提前 return → **版本索引从未落盘**；
3. 前端版本条 effect 只依赖 `sessionId` → **同会话内新版本永不出现**。
配套新增断言测试 `test_sheet_artifact_keys_match_orchestrator_reader`，防止键名再次漂移。

### 6.4 发布/部署要点

- 端口：Nginx `10008` → Backend `10007`；开发前端 `3001`（`backend/main.py` 默认 `127.0.0.1:8001`，可用 `HOST/PORT/UVICORN_WORKERS` 覆盖；**多 worker 需 Redis**）。
- 必填环境变量：`DATABASE_URL`、`OPENAI_API_KEY`、`AUTH_SECRET_KEY`。
- 生产建议必填：`REDIS_URL`（登录限流原子计数、审批跨实例广播、任务队列；留空仅内存 fallback，只适合单进程开发）。
- 内网依赖：基础镜像仓库 `172.73.0.156:85`（`python:3.13-slim`、`nginx:1.27-alpine`）；前端**本地打包**（Node 22+）后 `docker compose up -d --build`。
- 前端更新：`cd frontend && npm run build` → `cd ../deploy && docker compose up -d --build frontend`。
- 持久化：宿主机 `data/` → 容器 `/app/data/`（charts、design-systems、design-themes、layouts、skills、website-templates，运行时产物自动创建）。
- 健康校验：`curl http://localhost:10007/api/v1/health/`、`curl -I http://localhost:10008/`。
- 关键默认值：`OPENAI_BASE_URL=https://api.openai.com/v1`、`OPENAI_MODEL=gpt-5.4`、`AUTH_TOKEN_EXPIRE_MINUTES=10080`、`CORS_ALLOW_ORIGINS=http://localhost:3001`。
