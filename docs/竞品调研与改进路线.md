# 竞品调研与改进路线

> 2026-10 · 调研对象:Dify / Coze(Coze Studio) / n8n / Flowise / LobeChat / Open WebUI / Cherry Studio / FastGPT / MaxKB / AnythingLLM
> 用途:确定 AgenticOS 的下一步投入优先级

---

## 一、逐产品要点

|---|---|---|---|---|

## 二、对 AgenticOS 的改进建议

> **一处事实纠正**:原始调研结论称"AgenticOS 没有知识库 RAG 模块",经代码核实**不成立**——本项目已具备完整知识库管线(`app/services/knowledge/`:文档解析 markitdown → Wiki 自动编译(摘要/概念/事实三类页面)→ jieba 分词 + MySQL FULLTEXT 中文 BM25 检索),且已在实测中验证召回正确。因此下面 P0-1 的定位是"**增强现有模块**"而非"从零建设"。

### P0(决定产品是否"像个平台")

| # | 借鉴自 | 做什么 | 预期收益 |
|---|---|---|---|
| **P0-1** | Dify 切片/检索页、Cherry Studio 召回测试 | **增强现有知识库**:①切片参数可视化(分块大小/重叠/delimiter)②**召回测试页**(固定问题集 + 命中率/排序变化,改配置后回归对比)③TopK / 相似度阈值 / Hybrid 语义-关键词权重可调,且**明确标注"阈值仅在启用 rerank 后生效"**(Dify 的常见踩坑点)④可选 rerank | 中文企业文档(合同/规范)召回质量直接决定 RAG 能否交付;召回测试把调参从试错变成可复现流程,也是给客户看的交付物 |
| **P0-2** | Open WebUI 三档审批 | HITL 从"按工具勾选"升级为**会话级三档**:`ask`(全问)/ `auto`(**只读工具自动放行**:读文件/列目录/搜索/读 URL)/ `full`(全放,仅管理员) | 现有 HITL 要么全问(啰嗦)要么全放(危险);三档是最小改动换最大体验提升,可消掉约 80% 的确认弹窗 |
| **P0-3** | Dify / Flowise | **工作流画布 v1**:先做 8 个节点——开始 / LLM / 知识检索 / 工具 / HTTP 请求 / 代码 / 条件分支 / 结束,并**内置「人工输入(Human Input)」节点**(Dify 已有,是 HITL 产品的天然差异化)。workflow 可整体打包成"一个工具"喂给现有 Agent,与当前架构不冲突 | 没有画布就只能卖"对话";补上后能覆盖流程型业务需求 |
| **P0-4** | Open WebUI / Cherry Studio | **MCP 客户端支持**:管理端配置 MCP Server,工具自动发现并命名,支持 bearer token / 自定义 header | MCP 是 2025-2026 事实标准,现在补是窗口期 |

### P1(拉开体验差距)

| # | 借鉴自 | 做什么 |
|---|---|---|
| **P1-1** | Cherry Studio 创建向导 | 自建智能体(已实现)再升级为四步向导 + 编辑页分 tab(基础/提示词/工具/技能/知识库/MCP/高级);提示词给**结构化模板**(角色/目标/边界/输出格式)而非形容词堆砌 |
| **P1-2** | Cherry Studio 能力四分法 | 在 UI 上把 **工具 / 知识库 / 技能 / MCP** 四类能力视觉分开并各给一句解释("工具=能做什么;知识库=能查哪些资料;技能=按什么流程做事;MCP=能连哪些外部系统")。现有 skill_service 已有能力但没被讲清 |
| **P1-3** | Dify 运行限制 | 显式暴露运行预算(最大步数/工具调用数/超时)并在 UI 显示进度("第 7/10 步"),超限时给可操作的续跑提示,而不是静默截断 |
| **P1-4** | Open WebUI Plan mode | 计划模式:开启后剥掉写/命令工具,AI 只读调研产出计划,用户批准后切回执行;复用现有 DecisionPanel 渲染计划 |
| **P1-5** | FastGPT / Cherry Studio | 文档解析增强:PDF 表格与图片、扫描件 OCR、Office → Markdown 统一清洗管线(现有 file_to_md 工具可作为基础) |
| **P1-6** | Dify Summary Auto-Gen | 切片自动生成摘要并一并索引,命中摘要返回原块(开关式,因为要花钱) |
| **P1-7** | n8n / Dify 代码节点 | 工作流放行**受限代码节点**:沙箱、超时、内存与输出上限、禁网。一开始就做限制,而不是像 Coze 那样事后补安全 |
| **P1-8** | Dify / FastGPT 发布形态 | Agent/Workflow 发布为 **OpenAI 兼容 API + Chat SDK 嵌入**,复用现有 SSE 协议;这是企业把 AgenticOS 接进既有系统的唯一理由 |

### P2(精细化)

Agent 运行模式分层 / 文件变更以 diff 形式复核后再落盘 / DSL(YAML)导入导出 / 外部知识库 API 对接 / 集合标签与文件级权限 / 输入输出护栏 + 数据集回归评测 / AgenticOS 作为 MCP Server 被外部接入 / 召回测试常驻化。

## 四、给本项目的一句判断

AgenticOS 当前的差异化是"**产出物 + 强管控 + 私有化**"(可编辑 PPTX、可部署网站、工具级审批、数据不出内网),竞品在这三点上都不强。**P0 里最值得立刻做的是 P0-2(三档审批)**:改动小、直击"审批太啰嗦"这个真实痛点,且能复用现有 HITL 链路。其次是 P0-1 的召回测试——它是把知识库从"能跑"变成"能交付"的关键。
