前端主线

Chat 负责页面编排，useChatStream 负责发送、审批和乐观更新， sendMessageStream 负责解析 SSE 并把事件回调给 UI。

后端主线

/api/v1/agent/stream 把请求交给 AgentService.stream_chat， 它负责解析运行时 Agent、恢复会话、接入审批、记录 usage，并映射 SSE。

agent.py agent_service.py session_storage.py

PPT / 治理主线

PPT 模式在 done 时会生成 artifact；审批则由运行时命中 approval_tools 时触发，走 ApprovalManager 回推到前端。

一、聊天请求从前端到 Wuwei 再回前端的完整时序图

这张图把“正常回复主线”与“审批分支”“PPT artifact 分支”画在同一条时序里。 主干入口来自 frontend/src/hooks/useChatStream.ts、 frontend/src/services/agentService.ts、 backend/app/api/v1/endpoints/agent.py 和 backend/app/services/agent_service.py。

蓝色实线：HTTP / SSE 主干
绿色实线：Agent 运行时内部步骤
橙色虚线：审批分支 / 人机回路

时序图里最关键的设计点

  • 前端不是等完整回复才更新，而是先创建本地 session，再靠 SSE 不断补全。
  • 后端的 API 层很薄，真正的状态编排几乎都在 AgentService.stream_chat()。
  • 审批不是单独接口轮询模型状态，而是运行时通过 ApprovalManager 直接向 SSE 通道塞事件。
  • PPT artifact 不是另一条 API 任务队列，而是聊天运行结束后在同一轮 SSE 中产出的附加制品。

二、AgentProfile / ToolConfig / Skill / Approval 的领域关系图

这张图把“配置层”和“运行时层”分开画。 核心结论是：ToolConfig 主要定义模式级默认工具策略，AgentProfile 是真正面向用户的可安装 Agent 单元， Skill 通过多对多挂到 AgentProfile 上，而 Approval 不是静态配置实体，它是运行时根据工具审批策略产生的会话事件。

蓝色：配置关系 / 默认值来源
绿色：运行时对象组装
橙色：审批事件生成与会话归属

四个概念的正确理解

  • AgentProfile 是产品层实体，用户感知到的是它，不是裸 mode。
  • ToolConfig 主要提供模式级默认工具策略，并在启动时帮助补齐内置 Agent 的工具配置。
  • Skill 通过 AgentProfileSkillModel 多对多挂到 AgentProfile 上，进入运行时后变成 RuntimeSkill。
  • Approval 不是设计时配置，而是运行时命中 approval_tools 后落库的会话事件。

对应源码锚点

  • backend/app/db/models.py:127 定义模式级工具配置。
  • backend/app/db/models.py:140 定义 AgentProfile。
  • backend/app/db/models.py:158 定义 Agent 与工具的关联表。
  • backend/app/db/models.py:171 与 :185 定义 Skill 及其关联表。
  • backend/app/services/agent_profile_service.py 负责把配置层折叠成 RuntimeAgentProfile。
  • backend/app/db/models.py:227 定义 ApprovalModel。
